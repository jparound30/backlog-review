# 変更履歴

バージョンは `YYYYMMDD.N.0`（リリースした日と、その日の何回目か）。互換性のない変更があるときは「移行で必要なこと」に書く。

## 20261012.2.0（2026-10-12）

### 変わったこと
- レビューする側のスキル `backlog-review` が投稿した指摘（1 行目が「🤖 自動レビュー」、最後の行に `[review-bot finding …]`）を、`fetch` と確認①の一覧で「🤖 自動レビューの指摘（重大度）」と表示する。表示だけで、状態・ランク・返信の判定は変わらない
- 自動レビューの指摘では、一覧の要約・返信の引用・サマリーの要約列に、1 行目の印ではなく `指摘:` の行を使う
- レビュアー向けの説明（`references/reviewer-guide.md`）に「自動レビューの指摘」の節を追加
- `interpret --file` の解釈の JSON は、一時ディレクトリか `.review-state/` の下の自分の `.json` だけ読む（返信の本文と同じ制限）。JSON として読めないときに、ファイルの内容をエラーに出さない

### 移行で必要なこと
- 解釈の JSON を一時ディレクトリの外（対象リポジトリの中など）に置いていた場合は、`mktemp -d` で作った一時ディレクトリに置く（手順書はもとからそう指示している）。レビュアーに `reviewer-guide.md` の追記を知らせるとよい

## 20261012.1.0（2026-10-12）

最初の公開。

### できること
- Backlog の PR のレビューコメントを全件読み、指摘ごとに状態（未対応・修正済み・解決など）を管理する
- 場所と直し方がはっきりした指摘を修正し、指摘ごとに 1 コミットにして返信する。それ以外は確認の質問を返す
- 2 回の確認（対応する指摘の選択、push と投稿の承認）を挟んで進める
- PR にサマリーコメントを置き、進み具合と、レビュアーが次にすることを示す

### 移行で必要なこと
- なし
