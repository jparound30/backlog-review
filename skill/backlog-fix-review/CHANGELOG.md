# 変更履歴

バージョンは `YYYYMMDD.N.0`（リリースした日と、その日の何回目か）。互換性のない変更があるときは「移行で必要なこと」に書く。

## 20261024.1.0（2026-10-24）

### 変わったこと
- **完了した指摘の決着を表示する**: サマリーの状態の列で、完了（☑️ resolved）した指摘に、どう決着したかを括弧で添えるようにした（例: `☑️ resolved（見送り）`）。修正・回答・見送り・取り下げのどれか。見送り（wontfix）にレビュアーが納得して `✅` で解決しても、見送ったことが表から分かる。進み具合の件数の数え方は変わらない
- **対応の記録**: `export` の「対応区分」に「取り下げ」を加えた。`RC-番号 ✅ 対応不要`（または `✅ 修正不要`）で解決した指摘は「取り下げ」になる
- `references/reviewer-guide.md` のサマリーの見方に、括弧の意味を書き足した

### 移行で必要なこと
- **チームへの周知が必要**: サマリーの見方が変わる。レビュアーに `references/reviewer-guide.md` の「サマリーの見方」を知らせる
- マーカー・状態ファイル・CLI のコマンドは変わらない。以前のバージョンが書いた返信・サマリーは、そのまま読める
- `backlog-review` も同じバージョンにそろえる（サマリーの内容を合わせるため）

## 20261017.1.0（2026-10-17）

### 変わったこと
- **サマリーを PR の説明文に置く**: サマリーを、PR の説明文の末尾の区画（画面には出ない `<!-- review-bot summary begin -->` 〜 `end` の印で囲んだ部分）に置くようにした。レビュー側のスキル `backlog-review` からも同じ内容で更新される
  - 置き換えるのは区画の中だけで、作成者が書いた部分は変えない。区画の印が壊れていたら書き換えない
  - `summary` は、`--yes` なしで置き場所と区画を表示し、その後に説明文が編集されていないときだけ `--yes` で反映する。反映の直前にも取得し直して確かめる
  - 説明文を更新できないとき（権限がない・API が拒否した・区画の印が壊れている）は、今までどおりサマリーコメントを使う
  - 表の要約の列は省略しない
- **指摘の分類**: 指摘ごとに分類を 1 つ付ける（機能・ロジック / エラー処理 / セキュリティ / 性能 / 設計・保守性 / 規約・書式 / テスト / ドキュメント / その他）。解釈の JSON の `category` で付け、確認①の一覧に表示し、返信の `**場所**:` の次の行に `**分類**:` を書く。指摘の本文に `分類:` の行（自動レビューの指摘や、レビュアーが書いたもの）があれば、そちらを使う。分類は記録と表示だけに使い、自動で直すかどうかの判定は変わらない
- **対応の記録の出力**: `export <URL> [--all]` を追加した（読み取りだけで、Backlog には何も投稿しない）。指摘ごとの対応状況を、`.review-state/export/` に CSV（BOM 付き。Excel で開ける）と Markdown（集計つき）で出力する
  - CSV は指摘 1 件 = 1 行。本文と、やり取り（コメントを時系列に、日時・投稿者・種類つき）の列がある。値は省略せず、セルの中の改行も残す
  - Markdown は、集計（状態別・分類×状態・完了率・解決までの日数など）、一覧、指摘ごとのやり取り。一覧とやり取りはファイルの中のリンクで行き来できる
  - 数式として働く値・制御文字・秘密情報らしき文字列を処理する。出力先は変えられず、同じ名前のファイルは上書きしない
- 「この PR のレビューの記録を出して」と頼まれたときにもスキルが使われるよう、description に書き足した

### 移行で必要なこと
- **チームへの周知が必要**: サマリーの場所が、PR のコメントから PR の説明文の末尾に変わる。レビュアーに `references/reviewer-guide.md` の「サマリーの見方」を知らせる。以前のサマリーコメントは、説明文に移したときに「説明文に移しました」の文に書き換わる（印の行は残る）
- `summary --yes` の前に、`--yes` なしの `summary` で下書きを表示する必要がある（手順書は確認②で表示するよう直した）
- 解釈の JSON に `category`（指摘の分類）が要る。状態ファイルに残った以前の解釈はそのまま使える（その指摘の返信に分類の行が付かないだけ）
- 許可設定: 読み取りだけの `export` は許可リストに入れてよい（`references/details.md` の例に追加した）。`summary … --yes` は今までどおり入れない
- 以前のバージョンが書いた返信・サマリー・マーカーは、そのまま読める
- `backlog-review` も同じバージョンにそろえる

## 20261013.1.0（2026-10-13）

### 変わったこと
- Backlog のスペースによっては、UTF-8 の 4 バイト文字（多くの絵文字）を含むコメントを API が拒否するため、投稿する本文に 4 バイト文字を入れないようにした
  - 返信・サマリーの絵文字を Backlog の絵文字の記法にした（`🤖` → `:computer:`、`💬` → `:speech_balloon:`、`🙅` → `:no_good:`、`📝` → `:memo:`）。画面では絵文字として表示される
  - 返信の本文などに 4 バイト文字が残っていれば、投稿の前に `U+1F600` の形に置き換える。下書きにもその形で出る
- 本文の場所の印として、行の先頭の `場所: src/foo.ts L42` を読む。以前の `📍 src/foo.ts L42`（と記法の `:round_pushpin:`・`:pushpin:`）も引き続き読む
- レビュアー向けの説明（`references/reviewer-guide.md`）のテンプレートを `場所:` の形にし、4 バイト文字を使わない書き方にした

### 移行で必要なこと
- 以前のバージョンが書いた返信・サマリーはそのまま読める（判定はマーカーだけで行うため）。サマリーは次の更新で新しい書式になる
- チームへの周知が必要: レビュアーに、場所の書き方が `場所: ファイル L行` になったことを知らせる（`reviewer-guide.md`）
- `backlog-review` も同じバージョンにそろえる

## 20261012.2.0（2026-10-12）

### 変わったこと
- レビューする側のスキル `backlog-review` が投稿した指摘（1 行目が「🤖 自動レビュー」、最後の行に `[review-bot finding …]`）を、`fetch` と確認①の一覧で「🤖 自動レビューの指摘（重大度）」と表示する。表示だけで、状態・ランク・返信の判定は変わらない
- 自動レビューの指摘では、一覧の要約・返信の引用・サマリーの要約列に、1 行目の印ではなく `指摘:` の行を使う
- レビュアー向けの説明（`references/reviewer-guide.md`）に「自動レビューの指摘」の節を追加
- `interpret --file` の解釈の JSON は、一時ディレクトリか `.review-state/` の下の自分の `.json` だけ読む（返信の本文と同じ制限）。JSON として読めないときに、ファイルの内容をエラーに出さない

### 移行で必要なこと
- 解釈の JSON を一時ディレクトリの外（対象リポジトリの中など）に置いていた場合は、`mktemp -d` で作った一時ディレクトリに置く（手順書はもとからそう指示している）。レビュアーに `reviewer-guide.md` の追記を知らせるとよい

## 20261012.1.0（2026-10-12）

最初の公開。

### できること
- Backlog の PR のレビューコメントを全件読み、指摘ごとに状態（未対応・修正済み・解決など）を管理する
- 場所と直し方がはっきりした指摘を修正し、指摘ごとに 1 コミットにして返信する。それ以外は確認の質問を返す
- 2 回の確認（対応する指摘の選択、push と投稿の承認）を挟んで進める
- PR にサマリーコメントを置き、進み具合と、レビュアーが次にすることを示す

### 移行で必要なこと
- なし
