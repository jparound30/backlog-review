# backlog-fix-review

Backlog の PR に付いたレビューコメントを読み、**直し方がはっきりした指摘はコードを直してコミットし、各コメントに返信する**エージェント用のスキルです。指摘ごとの対応状況は、PR のサマリーコメントにまとめられます。

[Agent Skills](https://agentskills.io) の形式なので、Claude Code など対応するエージェントで使えます。

> **非公式のツールです。** 株式会社ヌーラボとは関係がなく、同社による提供・保証・サポートはありません。Backlog は株式会社ヌーラボの商標です。

## 必要なもの

- Agent Skills に対応し、シェルのコマンドを実行できるエージェント
- Node.js 20 以上と git（`npm install` は不要）
- Backlog の API キー（個人設定 → API で発行）。キーは**あなたのすべての権限**を持つので、チャットに貼ったりコミットしたりしない
- 対象リポジトリの clone（PR のブランチを checkout した作業ディレクトリ）

## 導入

1. **スキルを置く**: このフォルダを、名前を変えずにスキルの置き場所へコピーします。
   ```bash
   cp -R backlog-fix-review ~/.claude/skills/
   ```
2. **環境変数を設定する**: エージェントを起動するシェルで設定します。`BACKLOG_SPACE` 以外のホストには API キーを送りません。
   ```bash
   export BACKLOG_API_KEY='（API キー）'
   export BACKLOG_SPACE='yourspace.backlog.jp'
   ```
3. **許可設定を確かめる**: 自動承認のモードでは使わず、`curl` などの任意のコマンドを許可しないでください。読み取りだけのコマンドは許可してかまいません（設定例は [詳細](references/details.md#エージェントの許可設定)）。

## 使い方

PR のブランチの作業ディレクトリでエージェントを起動し、URL を示して頼みます。

```
https://yourspace.backlog.jp/git/PROJECT/repo/pullRequests/42 のレビュー指摘に対応して
```

Claude Code では `/backlog-fix-review <PR の URL>` でも起動できます。あとはエージェントが次のように進め、主に **2 回**あなたに確認を求めます（ほかに、コマンドの許可や、直し方の選択肢・見送りの判断を尋ねられることがあります）。

1. コメントを読み、指摘ごとに場所・直し方・影響範囲を判定する
2. **確認①**: 一覧を見て、対応する指摘を `1,3-5` / `all` / `none` で選ぶ
3. 選んだ指摘を直し、指摘ごとに 1 コミットにする（テストも実行する）
4. **確認②**: 差分の全文と返信の下書きを見て、push と投稿を承認する
5. push して返信し、サマリーを更新する

エージェントの環境で git の push ができない場合は、確認②の後に自分で push と `git fetch` をしてから、エージェントに続きを頼んでください。

自動で直すのは、**場所が確定し、直し方が 1 通りで、影響がその箇所だけ**の指摘だけです。それ以外は直さずに、確認の質問を返信します。選ばなかった指摘は未対応のまま残り、もう一度実行すると続きから対応できます。

**対応の記録**: 「この PR のレビューの記録を出して」と頼むと、指摘ごとの対応状況（指摘者・分類・対応内容・コミット・解決日時など）を CSV（Excel で開ける）と Markdown（集計つき）にして、`.review-state/export/` に出力します。Backlog には何も投稿しません（[詳細](references/details.md#作成されるファイル)）。

## レビュアーに伝えること

[reviewer-guide.md](references/reviewer-guide.md) をチームに共有してください。大事なのは次の 2 つです。

- 返信は **`RC-番号` で始める**（番号はサマリーの表の RC 列）
- 解決したら **`RC-番号 ✅`**、対応不要なら `RC-番号 ✅ 対応不要`

## 必ず守ること

- **1 つの PR は、同じ人のアカウントでだけ対応する。** 返信はあなたのアカウントから「💻 自動対応」として投稿されます。別の人が引き継ぐと、前の返信が新しい指摘として扱われます。
- **確認②では差分の全文を読む。** コメントに誘導された変更が紛れていないかを確かめる最後の機会です。
- **信頼できない人のコメントがある PR では、サンドボックスやコンテナで動かす。** 修正したコードやテストはあなたの権限で動き、API キーなどの資格情報を読めるためです。
- 対象リポジトリに作られる `.review-state/` は、コミットしない（コメントの本文が含まれます）。
