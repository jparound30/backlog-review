# 変更履歴

バージョンは `YYYYMMDD.N.0`（リリースした日と、その日の何回目か）。`backlog-fix-review` と同じリポジトリで同じバージョンを付ける。互換性のない変更があるときは「移行で必要なこと」に書く。

## 20261017.1.0（2026-10-17）

### 変わったこと
- **サマリーを更新する**: `summary <URL> [--yes]` を追加した。PR の説明文の末尾の区画（画面には出ない `<!-- review-bot summary begin -->` 〜 `end` の印で囲んだ部分）に、対応側の `backlog-fix-review` と同じ内容のサマリーを反映する。指摘や解決を投稿した後に使う
  - 置き換えるのは区画の中だけで、作成者が書いた部分は変えない。`--yes` なしで表示した後に説明文が編集されていなければ、`--yes` で反映する
  - 説明文を更新できないとき（権限がない・API が拒否した・区画の印が壊れている）は、サマリーコメントは投稿しない（サマリーは対応側が更新する）
- **指摘の分類**: 指摘の JSON に `category`（必須）を足した。投稿する指摘の `場所:` の次の行に `分類: エラー処理` のように書き、確認①にも表示する。対応側はこの分類をそのまま使う。分類は記録と表示だけに使い、対応側が自動で直すかどうかには影響しない
- **対応の記録の出力**: `export <URL> [--all]` を追加した。対応側の `export` と同じ CSV と Markdown を `.review-state/export/` に出力する（読み取りだけ）。レビュー側では、まだ自動返信のない人間の指摘の分類と、返信しない指摘の判定は補わない（注記に出る）
- 「この PR のレビューの記録を出して」と頼まれたときにもスキルが使われるよう、description に書き足した

### 移行で必要なこと
- 指摘の JSON に `category` が要る。以前のバージョンで作った下書き（`category` なし）は `post` で拒否されるので、`draft` からやり直す
- 許可設定: 読み取りだけの `export` は許可リストに入れてよい（`references/details.md` の例に追加した）。`summary … --yes` は、投稿と同じく許可リストに入れない
- 以前のバージョンが投稿した指摘（`分類:` の行なし）は、そのまま読める
- `backlog-fix-review` も同じバージョンにそろえる（サマリーの置き場所と、分類の読み取りを合わせるため）

## 20261013.1.0（2026-10-13）

### 変わったこと
- Backlog のスペースによっては、UTF-8 の 4 バイト文字（多くの絵文字）を含むコメントを API が拒否するため、投稿する本文に 4 バイト文字を入れないようにした
  - 指摘の 1 行目と重大度を Backlog の絵文字の記法にした（`:computer: 自動レビュー`、`:rotating_light:` critical / `:warning:` warning / `:bulb:` suggestion）。再レビューと「指摘なし」の見出しも同じ
  - 指摘の場所を `📍 \`path\` L42` から `場所: \`path\` L42` に替えた
  - 指摘や再レビューの文に 4 バイト文字が残っていれば、`U+1F600` の形に置き換える。確認②の全文にもその形で出る
- 重複の検査は、以前の `📍` の指摘も同じ場所として扱う

### 移行で必要なこと
- `backlog-fix-review` も同じバージョンにそろえる。それより前の対応側は `場所:` から周りのコードを切り出さない（場所は本文に書かれているので、解釈はできる）

## 20261012.2.0（2026-10-12）

最初の公開。

### できること
- Backlog の PR の差分を読み、指摘を、対になるスキル `backlog-fix-review` が自動修正できる書式（`📍` 場所・`指摘:`・`期待:`）で 1 指摘 1 コメントとして投稿する
- 既存の指摘との重複、PR の変更ファイル外・変更のない行への指摘、注意が要る表現を確認①で警告する
- 対応側の返信があれば、コミット（push 済みか・差分）と指摘の行の現在の内容を見せ、解決（`RC-番号 ✅`）・再指摘・回答を投稿する
- 2 回の確認（投稿する指摘の選択、投稿の承認）を挟んで進める。`--yes` は直前に表示した本文と同じときだけ投稿する。レビューの観点は対象リポジトリのドキュメントから読む
- 公開前のセキュリティレビュー（独立したエージェント）の指摘 14 件のうち 13 件に対応（詳細は開発元の `docs/plan-review.md` §6-1）

### 移行で必要なこと
- なし（最初の公開）
